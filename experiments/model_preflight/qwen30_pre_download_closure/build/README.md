This is a future CPU-only Linux build bundle. No image was built on the current Windows host; no package wheel or Debian package bodies have yet been collected. Public source code archives and metadata are included. No Qwen body is an input to these scripts.

1. Copy this dedicated directory to an isolated Linux amd64 build workspace. Verify artifact_manifest.json before using it. Install/use an authenticated preparation Python environment with packaging for the collector (it performs metadata validation only).
2. Invoke `python3 -B build/collect_inputs.py --collect-runtime-packages`. The collector stages allowlisted runtime package bodies, verifies exact SHA256 and wheel metadata closure, and produces a separate build_context. Failure retains evidence and stops without retry. Do not reuse an incomplete context or regenerate locks around a failure.
3. Authenticate/pull the exact FROM digest with the build engine; retain its OCI descriptor and verified layer receipts. No GPU device is exposed to the build. BuildKit/frontend/engine identities must be recorded by the target build operator, alongside kernel and compiler outputs. No upstream mutable Dockerfile, network bootstrap or runtime package solving is used.
4. Supply the actual selected-device compute architecture as an explicit build parameter and bind the inventory hash before acquisition. Invoke `python3 -B build/build_image.py --build --target-arch <attested CC>`. The Docker build runs with network=none. Source_DATE_EPOCH, jobs, compiler names, source pins and dependencies are fixed; bit-identical output across different build engines is not asserted without reproduction evidence.
5. `python3 -B build/verify_build.py build/target_build` checks the built image/installed identities. Retain build stdout/stderr, exact generated wheel SHA, self-test, SBOM, local image config digest, saved archive SHA, and engine/kernel/input/architecture binding. A local config digest and an OCI archive hash are distinct from a registry manifest digest. No registry digest is invented and no push is authorized by this step.
6. On a future host, separately run the CPU-only isolation probe against invented mock mounts. Bind its actual receipt to target_probe.py output. A successful build-time self-test is not target-runtime PASS, model fit, Gate A/B PASS or authority to acquire.

Pending target obligations: trusted Ubuntu InRelease signatures, complete base dpkg compatibility, actual package-body metadata validation, CPython and vLLM compilation/ABI, compiled architecture and attention kernels, build engine identity, installed binary/SBOM hashes and final image digest. The build fails closed on any mismatch; no version substitution or automatic repair is implemented.
